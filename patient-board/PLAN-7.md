# 7단계 계획: 실시간 동기화 + 직원별 로그인

## 확정된 결정 (원장님, 2026-10)
- **서버**: Supabase, **서울 리전(ap-northeast-2)**으로 프로젝트 생성. 프로젝트 생성 시 리전 목록에 Seoul이 보이는지 직접 확인.
- **보관 기간**: 이동 기록과 귀가 처리된 카드(이름·생년월일 포함)는 **7일 후 자동 삭제**.
- **직원 계정(개인별, 공용 계정 금지)**: 박유빈 코디, 김도은 코디, 정선영 실장, 백원경 간호사, 이소미 간호사, 이채영 간호사, 원장. 퇴사 시 계정 비활성화.
- **실제 환자 정보 사용 시점**: 로그인과 서버 보안(접근 통제)이 붙은 뒤부터.
- 방 이름은 지금 바꾸지 않음 (현재 이름 유지).

## 아직 확인이 필요한 것 (병원 개인정보 담당자/자문)
- 해외 회사가 운영하는 서비스에 환자 이름·생년월일·수술명을 두는 것의 개인정보보호법상 문제(국외 이전·위탁 여부).
- 이 보드의 정보가 의료법상 보관·보호 규정에 해당하는지.
- Supabase의 보안·개인정보 인증 범위 (공식 문서 직접 확인).

## 만들 것
1. DB 표 4개: rooms, patients, moves, staff(프로필: 이름, 역할, 활성 여부). 모든 표에 로그인한 직원만 읽기·쓰기(RLS).
2. 로그인 화면(이메일+비밀번호). 로그인하지 않으면 보드 접근 불가.
3. 실시간 동기화(Supabase Realtime): 한 곳에서 옮기면 1~2초 안에 다른 화면에 반영.
4. 이동 기록에 "누가 옮겼는지"(로그인한 직원) 저장.
5. 담당자 목록을 직원 계정에서 가져오기 (지금은 유빈/도은/정실장 예시).
6. 7일 지난 귀가 카드·이동 기록 자동 삭제(스케줄 작업).
7. 퇴사 처리: 직원 비활성화 시 즉시 로그인 불가.

## 원장님이 직접 해야 하는 것
- Supabase 계정 생성, **서울 리전**으로 새 프로젝트 만들기 (결제·개인정보 책임이 있어 대신 만들지 않음).
- 프로젝트 주소(URL)와 공개용(anon/publishable) 키를 알려 주기. **비밀(service_role) 키는 공유하지 말 것.**
- 직원 7명의 로그인용 이메일 정하기.
