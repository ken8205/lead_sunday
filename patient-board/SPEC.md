# 페이스플러스 환자 동선 보드 기획서 (Claude Code용)

2026-10-02

병원 2D 평면도 위에서 환자 이니셜 카드를 방으로 옮겨, 원장과 직원이 지금 누가 어느 방에 있는지 실시간으로 보는 웹앱입니다. 네이트온 동선창을 대체하는 것이 목표입니다.

## 사용자와 사용 장면

입력은 주로 유빈코디가 하고, 원장은 보기만 하는 구조입니다. 입력이 네이트온보다 쉬워야 정착합니다.

| 사용자 | 하는 일 | 기기 |
| --- | --- | --- |
| 유빈코디 | 환자 접수 시 카드 생성, 안내할 때마다 카드를 방으로 이동 | 데스크 PC, 태블릿 |
| 도은코디, 정실장 | 필요 시 카드 이동, 상태 변경 | 데스크 PC |
| 원장 | 지금 누가 어느 방에 있는지, 누가 오래 기다리는지 확인 | 진료실 PC, 폰 |
| 수술방 | 수술실·회복실 환자 상태 변경 | 수술방 PC 또는 태블릿 |

대표 장면: 원장이 시술을 마치고 폰을 열면 "시술2 최OO 준비 완료, 8분 대기"가 바로 보여 다음 방으로 갑니다.

## MVP 기능

첫 버전은 아래 다섯 가지만 만들고, 통계나 알림은 정착한 뒤에 붙입니다.

1. 2D 평면도: 방마다 사각형과 이름 (데스크, 대기실, 상담1, 원장실, 촬영실, 시술1, 시술2, 수술실, 회복실, 파우더룸 등). 방 배치와 이름은 설정 화면에서 수정 가능.
2. 환자 카드: 이니셜, 시술명 약어, 담당자, 들어온 시각. 데스크에서 "+" 한 번으로 생성.
3. 카드 이동: 드래그 앤 드롭 또는 카드를 탭한 뒤 방을 탭. 태블릿에서 손가락으로 쉽게 되어야 함.
4. 상태 표시: 대기 / 준비 완료(원장 대기) / 진행 중 / 귀가. 카드 색으로 구분하고, 준비 완료는 눈에 띄게.
5. 대기 시간: 현재 방에 들어온 뒤 경과 시간을 카드에 표시. 기준 시간(예: 10분)을 넘기면 강조.

공통 요구사항

- 여러 기기에서 동시에 보고, 한 곳에서 옮기면 1~2초 안에 모든 화면에 반영.
- 이동 기록은 자동 저장 (누가, 언제, 어디서 어디로).
- 하루가 끝나면 "귀가" 처리된 카드는 보드에서 사라지고 기록만 남음.
- 로그인한 직원만 접근.

## 화면 구성과 데이터 구조

화면은 세 개면 충분합니다.

| 화면 | 내용 | 주 사용자 |
| --- | --- | --- |
| 보드 | 평면도 + 환자 카드. 오른쪽에 "준비 완료" 환자 목록 | 전 직원, 원장 |
| 원장 모바일 보기 | 평면도 대신 방별 목록. 준비 완료 환자가 맨 위 | 원장 |
| 설정 | 방 추가·이름 변경·배치, 직원 계정, 대기 기준 시간 | 원장 |

데이터는 네 가지입니다.

| 데이터 | 주요 필드 |
| --- | --- |
| rooms | id, 이름, 평면도상 위치와 크기 (x, y, w, h), 순서 |
| patients (당일 카드) | id, 이니셜, 시술 약어, 담당자, 현재 방, 상태, 현재 방 입실 시각, 생성 시각 |
| moves (이동 기록) | 환자 id, 출발 방, 도착 방, 상태, 시각, 입력한 직원 |
| staff | id, 이름, 역할, 로그인 정보 |

## 기술 스택, 배포, 개인정보 원칙

실시간 동기화와 로그인이 기본 제공되는 서비스를 쓰면 서버를 직접 관리하지 않아도 됩니다. 아래는 제안이며 Claude Code에서 다른 조합을 골라도 됩니다.

- 프론트엔드: React + Vite, 평면도는 SVG로 그림. 태블릿·폰에서 쓰도록 반응형, 홈 화면에 추가 가능한 PWA.
- 실시간 DB와 로그인: Supabase (Postgres + Realtime + Auth) 또는 Firebase. 데이터 위치를 한국 리전으로 고를 수 있는지 확인.
- 배포: Vercel 등 정적 호스팅. 직원은 주소 하나로 접속.

개인정보 원칙 (이 앱에서 꼭 지킬 것)

- 실명, 연락처, 주민번호는 저장하지 않음. 이니셜과 시술 약어만.
- 차트번호도 넣지 않음. CRM과 연결은 하지 않는 것이 MVP 원칙.
- 직원별 개인 계정으로 로그인, 공용 계정 금지. 퇴사 시 계정 비활성화.
- 이동 기록은 일정 기간(예: 3개월) 후 자동 삭제 또는 익명화. 보관 기간은 원장이 결정.

## 단계별 계획과 정해야 할 것

두 군데 입력은 정착을 막으므로, 시범 기간이 끝나면 네이트온 동선창과 이 앱 중 하나만 남깁니다.

1. 1단계 시제품: 평면도, 카드 생성·이동, 실시간 반영. 원장 혼자 데스크 PC와 폰으로 테스트.
2. 2단계 시범 운영 (1~2주): 네이트온 동선창 대신 사용. 유빈코디 입력 속도와 불편한 점 기록.
3. 3단계 정착: 직원 의견 반영 후 네이트온 동선창 종료.
4. 4단계 확장: 대기 시간 통계, 방별 사용률, 원장 호출 알림 등.

정해야 할 것

- [ ] 실제 방 목록과 대략적인 배치 (손으로 그린 평면도 사진이면 충분)
- [ ] 상태 단계가 위 네 가지로 충분한지
- [ ] 대기 강조 기준 시간 (예: 10분)
- [ ] 사용할 기기: 데스크 태블릿 추가 여부
- [ ] 이동 기록 보관 기간
