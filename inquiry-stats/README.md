# 페이스플러스 상담 통계

유입 경로별 마케팅 효과와 추이를 보는 병원 직원 전용 앱입니다. **하루 기록장** 방식으로, 그날 일어난 일을 그날 카드 한 장씩 적고 예전 기록은 찾아 고치지 않습니다.
환자 동선 보드(`../patient-board`)와는 별도 앱이며, 같은 기술(React + Vite + Supabase)과 같은 직원 계정 구조를 씁니다.

## 실행

```bash
npm install
npm run dev      # 개발 서버 (http://localhost:5173)
npm run build    # 타입 검사 + 배포용 빌드 (dist/)
```

## 화면

- **오늘 기록** (전 직원): 문의·상담·시술 버튼과 오늘 건수·매출. 그날 당일 적는 것이 원칙입니다. 기록마다 수정·삭제가 있고, 날짜 옆 ‹ › 나 날짜 칸으로 지난날을 찾아 빠뜨린 것을 적거나 잘못 적은 것을 고치거나 지울 수 있습니다(전 직원).
- **통계** (원장·실장만): 기간(오늘·어제·이번 달·지난 달·최근 3개월·최근 12개월·올해·직접 선택, 직접 선택은 날짜 단위)별 문의·상담·시술·매출 요약, 경로 매출 순위 시상대(1~3위)와 문의왕·시술왕·가성비왕, 추이 그래프(문의·상담·시술·매출 중 하나씩 막대로, 일간 30일·주간 12주·월간 12개월·연간 5년, 경로별로 골라 보기), 항목별 표(유입 경로·문의 채널·국적·시술), 광고비·수수료 입력.
- **항목 관리** (전 직원): 유입 경로·문의 채널·국적·시술 목록 추가·순서 변경·삭제.

## 기록 규칙

| 카드 | 언제 | 적는 것 |
|---|---|---|
| 문의 | 처음 연락 온 날 1장 | 유입 경로, 문의 채널, 국적, 관심 시술 (누구인지는 적지 않음) |
| 상담 | 병원에서 상담한 날 1장 (재상담도 1장) | 유입 경로, 국적, 관심 시술, 이름(선택) |
| 시술 | 수술·시술한 날 1장 | 유입 경로, 국적, 시술, **총액**, 이름(선택) |

- 모든 카드에 유입 경로를 붙입니다. 모르면 "모름".
- 워크인(예약 없이 온 환자)으로 상담 카드를 만들면 문의 1장이 같이 생깁니다.
- 한 환자가 같은 날 여러 시술을 받으면 시술 1장, 총액은 합쳐서.
- 패키지·회차 시술은 첫 회에 총액 전부, 2회차부터는 적지 않습니다.
- 에이전시 경로(기본: 미뷰·메이비·해외에이전시, 항목 관리에서 체크)는 해외에서 예약금을 내고 확정해 오므로 시술 카드만 적습니다(0-0-1). 문의→상담·상담→시술 비율 계산에서 빼고, 시술 건수·매출·마케팅비로 평가합니다.
- 매출 = 시술 카드 총액 합 (발생주의). 예약금은 매출이 아니고, 예약 후 취소는 시술 카드가 없으니 매출에 안 들어갑니다.
- 비율(문의→상담, 상담→시술)은 같은 기간 건수끼리 나눈 값입니다. 시차가 있어 주 단위로는 흔들리고 월 단위 이상이면 대체로 맞습니다.
- 광고비는 달 단위로 입력하므로, 날짜로 고른 기간에는 통째로 들어간 달의 광고비만 셉니다.
- 마케팅비 = 그달 광고비 + 수수료(그 경로 시술 총액 × 수수료율). 기본 수수료율은 메이비 30%, 미뷰 40%, 해외에이전시 30%이고 통계 화면 맨 아래에서 바꿀 수 있습니다.
- 주는 월요일 시작(ISO 8601). 건수 10건 미만의 비율은 흐리게 표시합니다.

## 서버 모드

환경 변수 두 개가 있으면 로그인 + 서버 저장, 없으면 이 브라우저에만 저장하는 시험 모드입니다.

```
VITE_SUPABASE_URL=https://<프로젝트>.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=sb_publishable_...   # 공개용 키만. secret/service_role 키는 절대 넣지 않음
```

- Supabase **서울 리전(ap-northeast-2)** 프로젝트의 SQL Editor에서 `supabase/schema.sql`을 실행합니다 (여러 번 실행해도 안전). 상담·시술 카드에 이름(선택)을 적을 수 있어 서울 리전을 씁니다. 보관 기간(자동 삭제)은 아직 정하지 않았습니다.
- **동선 보드와 같은 Supabase 프로젝트**에 실행하면 직원 계정을 그대로 씁니다 (권장: 직원이 계정 하나로 두 앱 모두 로그인).
- 이 앱의 표는 모두 `stats_`로 시작합니다(`stats_entries`, `stats_ad_costs`, `stats_commission_rates`, `stats_option_lists`). Table Editor에서 동선 보드 표(`patients`, `moves`, `rooms`)와 구분됩니다. 함께 쓰는 표는 직원 계정(`staff`) 하나입니다.
- 새 프로젝트에 실행하면 직원 계정을 따로 만들어야 합니다 (`../patient-board/supabase/create-staff.sql` 참고).
- 통계와 광고비 입력·조회는 원장·실장만 가능합니다 (광고비는 서버에서도 막음). 기록 입력·수정·삭제는 전 직원.
- 기록은 통계용이라 자동 삭제하지 않습니다.

## 배포 (Vercel)

동선 보드와 같은 방식으로 **Vercel 프로젝트를 하나 더** 만듭니다.

1. Supabase(동선 보드와 같은 서울 리전 프로젝트) → SQL Editor에서 `supabase/schema.sql` 전체를 붙여 넣고 실행합니다. 여러 번 실행해도 안전합니다.
2. Vercel → Add New → Project → 이 저장소(`lead_sunday`) Import.
3. **Root Directory**: `inquiry-stats`, **Framework Preset**: Vite (빌드 `npm run build`, 출력 `dist`).
4. **Environment Variables** (Production, Preview, Development 모두): 동선 보드와 같은 값
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY` (공개용 키만. secret/service_role 키는 절대 넣지 않음)
5. Deploy. Production은 `main` 브랜치를 따라갑니다.
6. 배포 주소를 열어 **로그인 화면이 나오는지** 확인합니다. 환경 변수가 빠지면 로그인 없는 시험 모드(예시 데이터)로 열리니, 그 상태로 실제 기록을 넣지 마세요.

환경 변수를 바꾸면 **Redeploy**해야 반영됩니다.

## 휴대폰·PC에 앱처럼 설치 (PWA)

배포 주소(HTTPS)를 연 뒤:
- **아이폰(사파리)**: 공유 버튼 → "홈 화면에 추가"
- **안드로이드(크롬)**: 메뉴(⋮) → "앱 설치" 또는 "홈 화면에 추가"
- **PC(크롬·엣지)**: 주소창 오른쪽 설치 아이콘

설치하면 주소창 없이 앱처럼 열립니다. 새 버전을 배포하면 다음에 열 때 바로 바뀝니다.
